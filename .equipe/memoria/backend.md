# Memória do backend — Rastreio-correios

- 2026-11-12 · Erro meu: escrevi `datetime(2026, 11, 5, 24)` num teste; hora 24 não existe. Use `0` do dia seguinte.
- 2026-11-12 · Padrão do projeto: testes que chamam `consulta_correios.processar()` patcham `consulta_correios.__file__` para uma pasta temporária `Arquivos/`, assim nada é gravado no repositório. Arquivos de estado novos devem ficar na mesma pasta do script, calculados a partir de `__file__`.
- 2026-11-12 · Padrão do projeto: o ruff (isort) exige que um import novo do pacote `correios` entre no bloco `from correios import (...)` em ordem alfabética, e não como linha separada.
- 2026-11-12 · Padrão do projeto: `processar()` trata exceções com `print` (ex.: "Aviso: ..."), não com `logging`. Mantenha o estilo.
- 2026-11-12 · Correção pedida pelo coordenador (QA bloqueante): validar cada entrada de dados lidos do JSON, e não só a raiz. `carregar()` descarta entrada sem data válida e registra aviso; `podar` e `entregas_da_semana` também ignoram entrada incompleta, para não derrubar `processar()`.
- 2026-11-13 · Padrão do projeto: lote que consulta item a item (rastreios, pedidos) não pode deixar uma falha derrubar o resto. Trate a falha por item, use o dado anterior e siga, como em `processar()`.
- 2026-11-13 · Erro meu num teste: um `write` falso que procura "keep-alive" também pegava o cabeçalho `Connection: keep-alive`. Em teste de SSE, identifique o evento pelo início da linha (`data: ` ou `: keep-alive`), e não por uma palavra qualquer.
- 2026-11-13 · Correção pedida pelo QA: `ServerLogQueue` não tem mais fila padrão nem `get()`. Quem quer ler os logs se inscreve com `inscrever()` antes de gravar, e `put()` nunca levanta exceção: a cópia para as filas acontece dentro da trava.
- 2026-11-13 · Padrão de teste: para provar uma corrida, rode o cenário com várias threads e conte as exceções; um teste de uma thread não pega isso.
- 2026-11-13 · Correção pedida pela revisão: em `processar()`, só erro da API dos Correios (`CorreiosError`, `requests.RequestException`) usa o dado anterior. `CorreiosAuthError` sobe (token recusado derrubaria todos os rastreios), e erro de programação não é engolido.
- 2026-11-13 · Padrão de teste de agendamento: não espere tempo real. `UpdateManager` recebe `relogio` e `dormir` injetáveis; o teste avança o relógio na própria espera e roda o laço em thread. Assim cada caso é determinístico e leva milissegundos.
- 2026-11-13 · Regra do laço automático: o worker reagenda `next_update_time` no `finally` (sucesso ou falha), e o laço espera o worker terminar antes de voltar a esperar. Sem essas duas coisas, o laço dispara duas vezes seguidas.
- 2026-11-13 · Padrão de escape: `cards.py` já escapa os campos do cartão; o que chega como HTML pronto (`formatar_evento_html`) e as linhas da tabela de atrasados escapam por conta própria. Não escape de novo o que já sai escapado.
- 2026-11-13 · Acentos: o PowerShell 5.1 (`Get-Content`) mostra UTF-8 como mojibake ("repositÃ³rio"). Antes de "corrigir" um arquivo, confira os bytes com Python (`read_bytes`) ou com a ferramenta Read. O `ci.yml`, o `tiny/exceptions.py` e o README estavam certos.
- 2026-11-13 · Teste que mocka `requests.get` precisa mockar no módulo onde a chamada acontece (agora `tiny.client.requests.get`). Mockar o alias de outro módulo deixa a chamada real correr, como aconteceu no vermelho de A10.
- 2026-11-13 · Ao mudar a assinatura de uma função mockada (ex.: `consultar_objeto` ganhou `cliente`), ajuste os fakes dos testes para `*_`.
- 2026-11-13 · Renovação de token: o 401 renova só se o token usado for o guardado pelo cliente; se outro rastreio já renovou, reaproveita o guardado. Depois da renovação, um 401 sobe `CorreiosAuthError`. Teste de rodada: emitir tokens em ordem e aceitar só um deles.
- 2026-11-13 · Correção pedida pela revisão: quem guarda o token é o cliente. O `processar()` não deve levar o token nas consultas (passa `None`); se levar o velho, cada rastreio refaz a consulta depois da renovação. E a renovação só reaproveita o token guardado se ele existir (`if self._token and ...`); sem isso manda "Bearer None".
- 2026-11-13 · Diagnóstico sem API: quando o sintoma varia por serviço e por pedido, não é campo com outro nome (um parse errado afetaria todos igual). Cruze o HTML salvo (serviço × prazo) antes de mexer no parse. Para diagnosticar depois, guarde o motivo no dado (`prazo_erro`), e não só no log.
- 2026-11-13 · "Dados de" é a hora dos dados consultados, e precisa ser a mesma nas quatro páginas. Página que gera a própria hora (`time.strftime`, `datetime.now`) mostra a hora errada. Passe `dados_em` explicitamente; não leia o relógio dentro da página.
- 2026-11-13 · Texto que quebra no celular: "1,9 dias" vira `1,9&nbsp;dias` e o rótulo "Mais demorado" usa `&nbsp;·&nbsp;`, para o "·" não abrir a linha. Dá para fazer sem CSS.
- 2026-11-13 · Sanitização de corpo de erro: a regra "chave: valor" não basta para `Bearer <segredo>` dentro de um JSON; o valor depois de `Bearer` vaza. Aplique primeiro a regra de `Bearer <valor>` e depois a de chave. Teste com o caso real que vaza: `"authorization":"Bearer ABC.def-9"`.
- 2026-11-13 · Resposta de API que não é dict quebra o `.get` antes de qualquer `except FreteError`; valide o tipo antes de usar `.get` e converta em erro tratado.
- 2026-11-13 · Cuidado com teste que escreve sequência de tokens: confira que o servidor fake aceita exatamente o token que a rodada deveria usar. Escrevi um caso que reaproveitava a mesma lista e quase testou o contrário.
- 2026-11-24 · Regra de divergência do Tiny: a linha "Situação no Tiny" some quando concorda e fica quando diverge. Uma regra nova não pode esconder um conflito que a regra antiga (`divergencia_tiny`) já aponta; use a união das duas (`situacao_tiny_visivel`).
- 2026-11-12 · Correção pedida pelo coordenador: o `processar()` não tem `try/except ImportError` para módulos do próprio projeto; import direto. Falha ao gerar uma página secundária vira aviso com `print`, e não devolve False.
